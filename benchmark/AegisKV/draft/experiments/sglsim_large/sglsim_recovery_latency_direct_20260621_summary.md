## Interpretation

The direct SGLSim serving-path replay evidence shows AegisKV restore choices
reduce recovery overhead relative to recomputing the same failure point, but
the improvement is more conservative than the earlier policy-model row. This
is a better preliminary Fig. 9 input because the AegisKV row now comes from
actual HTTP replay requests, hard scheduler kill/restart, runtime restore-plan
metadata, and scheduler-side restore sleep.

This is still not final physical KV-copy evidence. The replay rows materialize
target-rank device-cache metadata and sleep for the selected restore plan, but
real CUDA tensor KV movement remains future validation.
